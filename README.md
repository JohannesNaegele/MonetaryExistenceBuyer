# MonetaryExistenceBuyer — Lean 4 formalization of *Existence of a stationary monetary equilibrium with buyer-takes-all bargaining*

A Lean 4 / Mathlib formalization of the manuscript

> Johannes Nägele, *Existence of a stationary monetary equilibrium with buyer-takes-all
> bargaining* (manuscript, version of 2026-11-09).

The paper studies the divisible-money search model of Trejos–Wright (1995) and Molico (2006) with
buyer-takes-all bargaining and unbounded individual money holdings, and proves that a stationary
monetary equilibrium of every prescribed mean money stock exists **if and only if** `β c₀ > 1`,
where `c₀ = u'₊(0)` is the marginal composite utility at zero and `β = π/(r+π)` the effective
discount factor.

Every definition and every lemma, proposition, theorem and (mathematical) remark of the manuscript
is formalized, and **the formalization is complete: there is no `sorry` in the project**.
`#print axioms` for the main theorems lists only the standard axioms `propext`,
`Classical.choice`, `Quot.sound`. In particular the following are proved in Lean from scratch:
Brouwer's fixed point theorem (not in Mathlib), the finite-grid existence theorem (§3), the
passage to the limit (§4), the rescaling analysis (§5), the exclusion of asymptotic saturation (§6),
the exclusion of a jump at the origin (§7), the completion with deterministic payments and strict
concavity (§8), and the translation between the general model with physical output and the
buyer-takes-all specialization (§2, `General/`).

## Provenance and disclaimer

Unlike the manuscript, which was written by its author, **this Lean code was almost entirely
generated by large language models.** Anthropic's Claude (Claude Opus 5.5 in October 2026 and
Claude Fable 5.1 in November 2026, run as coding agents in Claude Code) wrote the definitions,
the statements, the proofs, and this README, working from the manuscript. The author directed the
work, fixed how the Lean statements are to mirror the paper, and checked the build and the axiom
audit; the proof scripts themselves were not written, and should not be assumed to have been read,
by a human.

Consequences for the reader:

* **What Lean guarantees does not depend on who wrote the code.** The kernel checks every proof;
  the project contains no `sorry`, and `#print axioms` lists only `propext`, `Classical.choice`
  and `Quot.sound` for the main theorems (see [Build](#build)). A language model cannot talk the
  kernel into accepting a wrong proof.
* **What Lean does not guarantee is that the formal statements say what the paper says.** The
  trust base of this project is the set of definitions (`AdmissibleUtility`, `Environment`,
  `IsGeneralEquilibrium`, `IsEquilibrium`, …) together with the statements of the main theorems,
  the [correspondence table](#correspondence-table) and the
  [list of deviations](#where-the-lean-proofs-deviate-from-the-manuscript). These are what a
  sceptical reader should compare with the manuscript.
* **The code reads like machine-generated code.** Proofs are long and repetitive, helper lemmas
  are ad hoc and sometimes duplicated across files, and little of the abstraction a human Mathlib
  contributor would introduce is present. The project is a certificate for the paper, not a model
  of Lean style, and it is not meant for upstreaming as is.


## Build

```sh
# once: Lean toolchain (elan) and the Mathlib cache
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh
lake exe cache get

lake build                      # whole project (a few minutes with the Mathlib cache)
lake build MonetaryExistenceBuyer.Main # main theorem and everything it needs
```

Open this folder (the one containing `lakefile.toml`) in VS Code with the Lean 4 extension.
Every `sorry` would show up as a warning; there is none. To list exactly which axioms a theorem
depends on:

```lean
import MonetaryExistenceBuyer
#print axioms Molico.main            -- propext, Classical.choice, Quot.sound
#print axioms Molico.main_physical_iff
#print axioms Molico.Environment.necessity_general
```

`scripts/axioms.lean` does this for all main results: `lake env lean scripts/axioms.lean`.

The GitHub Actions workflow in `.github/workflows/ci.yml` runs `lake build` on every push.

## Design decisions

* **Utility and marginal utility.** `u : ℝ → ℝ` with (U1)–(U6) on `[0,∞)`
  (`AdmissibleUtility`). `u'₋` is the left derivative (`derivWithin u (Iio x) x`), extended by
  `c₀` at `0`, exactly as in `def:primitives`.
* **General model.** `Environment` bundles `U, K, q̄, π, r` of `def:environment`; `K⁻¹` is
  `Function.invFunOn`. `IsGeneralEquilibrium θ T M V η κ` is `def:generaleq` with a trade kernel
  `κ : Kernel (ℝ × ℝ) (ℝ × ℝ)`; as in the manuscript the value function is only assumed
  continuous and nonnegative, and its boundedness on `supp η` is proved
  (`lem:stationaryvaluebound`). The Bellman equation is stated with Bochner integrals, so the
  structure carries two fields saying that the outer integrals in `eq:generalbellman` exist;
  this is the content of the equation when the integrals are read as Lebesgue integrals.
* **Grid in index form.** A grid function is `V : ℕ → ℝ` with `V i` the value at `i h`
  (`i ≤ N`, `R = N h`). The grid Bellman operator is then mesh-independent. The mesh enters only
  through the mean constraint of `𝒫_M(𝒳)` and through the direction `u₀`.
* **`lem:incr`** is formalized for the cumulative sequences `A`, `B` (rather than the increment
  tuples) as the max-plus convolution `maxConv`. Proved: monotonicity, discrete concavity, and
  the merge inequalities `eq:merge`. The sorted-sum identity is only an intermediate step of the
  manuscript's proof and is not needed downstream.
* **Continuation principle.** `thm:approx` rests on `lem:continuation`: if a homotopy is
  admissible at level `ϱ` of a gauge `g` (no `H_t` has a fixed point on `{g = ϱ}`) and `H_1` has
  no fixed point in `{g ≤ ϱ}`, then `H_0` has one in `{g > ϱ}`. Lean proves it as
  `Molico.continuation`, for compact convex sets in any finite-dimensional real normed space,
  by the manuscript's argument: Brouwer's theorem applied to
  `(t, x) ↦ (p(t + ϱ - g(x)), H_t(x))` on `[0,1] × D`.
* **Brouwer's fixed point theorem** (`Molico.brouwer`, not in Mathlib) is proved analytically
  (Milnor–Rogers style) in `Brouwer/`: a `C¹` approximation (Stone–Weierstrass) of a
  fixed-point-free self-map of the unit ball yields a `C¹` retraction onto the sphere
  (`Ball.lean`); no such retraction exists (`NoRetraction.lean`) because for `f_t = id + t(r - id)`
  the change of variables formula gives `vol B = ∫_B det Df_t` for small `t` (`Homotopy.lean`:
  `f_t` is a bijection of `B` by the inverse function theorem and connectedness), the right side
  is a polynomial in `t` (`DetPoly.lean`), and `det Dr = 0`. General compact convex sets reduce to
  the ball by a linear chart and the nearest-point retraction (`Projection.lean`).
* **Weak convergence** is `WeakConv` (integrals of bounded continuous functions converge),
  which for probability measures coincides with Mathlib's topology on `ProbabilityMeasure`.
  Normalized wealth `[0, ∞]` is `ℝ≥0∞`.
* **Selected sequences** (`def:selected`) are a structure `SelectedSeq` bundling the
  approximants and their Helly/weak limits, including the limiting value distribution `ν`
  (`eq:valuelimit`). A *normalized limit* (`def:normalization`) is a structure `NormalizedLimit`,
  constructed for the levels `0 < a < J₀` of a bad sequence. "Pass to a further subsequence" is
  `SelectedSeq.comp`.

## Where the Lean proofs deviate from the manuscript

All deviations are simplifications or reroutings; no statement was weakened.

* `rem:physicaloutput` is proved in the strong form that every kernel `κ_{b,s}` (not only
  `η ⊗ η`-a.e.) is carried by the bargaining set: `Γ` is disintegrated over `(b, s)` (Mathlib's
  `condKernel`) and the exceptional null set is repaired with a measurable maximiser (the largest
  one; measurable because `H_V` is continuous by Berge's maximum theorem). For deterministic
  `Γ` the kernel is Dirac at a measurable payment rule. The Bellman equation of the
  reconstructed equilibrium is `buyerreduction_bellman`.
* `lem:buyerreduction` (the reduction `eq:buyerflow`) is formalized for admissible value
  functions (`IsValueFn`: bounded, continuous, increasing, concave, `V(0) = 0`), which is the
  only case used, rather than for arbitrary increasing `V`.
* `thm:halflevel` is proved directly on the approximants (rescaling `V_n` at the first crossing
  of the level `ℓ₀` and extracting a Helly limit), which is the manuscript's argument without
  routing it through the joint state distribution `α` of `def:normalization`. Accordingly,
  `NormalizedLimit` is only constructed for levels `0 < a < J₀` of a bad sequence
  (`normalizedLimit_exists`), the only case where it is used afterwards.
* `lem:coeff`, `thm:wdf`, `lem:inversion` and `thm:splitting` take `α({s = ∞}) = 0` as an explicit
  hypothesis; the manuscript derives it from `prop:count` inside the proofs. In Lean the
  hypothesis is discharged by `NormalizedLimit.count` where the results are used (`noplateau`).
* `thm:wdf` does not need the hypothesis `C̄ ≤ σ` to be derived inside: it is an explicit
  hypothesis, discharged by `coeff`; with the convention `u'₋ = c₀` on `(-∞, 0]` the integrand
  is defined for all sellers.
* `prop:passage` (3): the Bellman equation is obtained by a Tietze extension of `ℋ(m; ·)` off
  `ℰ_W` and uniform convergence of the grid payoffs in the seller, instead of the joint-law
  argument.
* `thm:splitting` avoids the auxiliary constant `ς` and uses `ω = 1/(4R)`; `lem:inversion` is
  applied to full sequences built from a violating subsequence.
* `prop:necessity` at `θ = 1` for the buyer-takes-all form `def:eq` is, in addition to the
  general theorem, also proved directly (`necessity`); `main` uses the direct proof, while
  `main_physical_iff` uses `necessity_general` as in the manuscript's proof of `thm:main`.
* In `lem:stationaryvaluebound` the identity `E[Y - X] = 0` of the coupling argument is not
  needed: integrability of the one-period value increments (obtained by Fatou's lemma from the
  truncations) already gives `V ∈ L¹(η)`, and the supersolution argument for `(V - ū/σ)₊` is
  carried out with `ℝ≥0∞`-valued integrals.
* In `prop:necessity` the essential supremum `L` is `sInf {c | V ≤ c η-a.e.}`, and the
  first-order condition for the Nash product (`eq:buyersurplusbound`) is derived from
  maximality at a slightly reduced output and elementary logarithm bounds, without
  differentiating; the degenerate case of a vanishing seller surplus at the maximiser is handled
  explicitly.
* In `prop:strictconcavity` "affine on an interval" is replaced by the midpoint identity
  `V(a + h/2) = (V(a) + V(a + h))/2`, which is equivalent for concave `V` and is exactly what the
  argument produces and consumes.
